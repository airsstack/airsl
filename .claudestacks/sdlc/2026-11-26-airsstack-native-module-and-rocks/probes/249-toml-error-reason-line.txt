# Probe 249 — `{toml error}` in form B: toml 1.2.2's first error line, `: `, then the reason line
question: author decision 2026-11-26 (form B for docs-check's "is not valid TOML" message, spec §5.6.3): `{toml error}` is the
  first line of toml's error Display, then ": ", then the reason. Which line is the reason, and does the rule give one non-empty
  line for every kind of invalid manifest? The rule probed (src/main.rs `toml_error`): split the Display with `str::lines`;
  keep the first line; the reason is the last line after the first that is not empty; when there is none (a Display of one
  line), `{toml error}` is the first line alone. Cases: probe 244's six, then kinds chosen to break it: a CRLF file, an error
  with no span (the key recursion limit, 100 dotted parts: toml's `de/parser/key.rs:67-68` reports `ParseError::new("recursion
  limit")` with no `with_unexpected`, and `de/error.rs:117-160` prints the source excerpt only when there is a span), nesting
  past the parser's depth limit, a date-time error (text from toml_datetime), `\n` in the expected list (`render_literal`
  prints it as "newline", `de/error.rs:93-96`), a bare carriage return, an invalid escape, an error at the end of a file with no
  final newline, a dotted key extending a value.
answer: every error with a span prints five lines (the position line, a three-line excerpt, the reason) and the reason is one
  non-empty line; the message becomes, e.g., "crates/airsl/Cargo.toml: is not valid TOML: TOML parse error at line 1, column 9:
  unclosed table, expected `]`". The error with no span prints one line, "recursion limit", and no position: the first line is
  then NOT "TOML parse error at …", and the rule gives "… is not valid TOML: recursion limit". No case gave a reason of several
  lines or an empty one. A CRLF file's excerpt line keeps its `\r` ("1 | [package\r\n"), which `str::lines` leaves on the
  excerpt line only; the first and last lines carry none.
versions: rustc/cargo 1.94.1 (the repository's rust-toolchain.toml, copied); toml 1.2.2+spec-1.1.0 with the workspace's features
  (std, serde, parse; Cargo.toml:48) and the workspace's Cargo.lock versions of its dependencies, pinned in this probe's
  Cargo.lock (toml_parser 1.1.6+spec-1.1.0, toml_datetime 1.1.3+spec-1.1.0, serde_core 1.0.229, serde_spanned 1.1.3, winnow
