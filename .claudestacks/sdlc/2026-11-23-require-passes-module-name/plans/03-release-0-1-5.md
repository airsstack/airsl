# Release airsl 0.1.5 and airsl-cli 0.1.5 Implementation Plan

**Goal:** Prepare both crates for publication as 0.1.5.

**Architecture:** One release commit, as the earlier releases used. It bumps both member versions
and the root `[workspace.dependencies]` entry together (spec §8, `workspace.md`), refreshes the
book transcripts that print the version (spec §7), and turns the CHANGELOG's `Unreleased` section

after merge (spec §8).

**Tech Stack:** Cargo, cargo-make (`dod`, `publish-dry-run`, `book-build`).

**Content authority:** spec §7 (version transcripts, kept-at-0.1.4 list, CHANGELOG) and §8.

## Risks

- **Publishing only one crate** reaches nobody, because the binary's lockfile pins the library.
  The plan bumps both; the author publishes `airsl` first, then `airsl-cli` (spec §8).
- **A missed version line** leaves the book claiming 0.1.4. The `git grep` check catches it.
- **What `publish-dry-run` covers.** It gives `airsl` a full `cargo publish --dry-run`, and
  `airsl-cli` only `cargo package --list`. That is by design (`Makefile.toml:203-226`): the
  `airsl` 0.1.5 that `airsl-cli` depends on reaches crates.io only when the author publishes it.
  The task must pass. It does not prove that `airsl-cli` resolves against the published `airsl`;
  the author's real publish, `airsl` first, is where that is checked.
